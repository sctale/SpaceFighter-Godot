# Phase 0 报告 6/6：重构风险与决策点（refactor_risks）

> 基线：`3371cfc`（v1.4.3）。本文件列出进入 Phase 1 前必须由用户拍板的决策，以及各阶段风险与缓解。

## 一、三个必须先拍板的决策点

### R1 技术路线：文档假设 Control/Theme，项目现实是立即模式 ★最大决策

文档建议「优先 Godot Control/Container/Theme/Signal」，但同时要求「必须先检查现有架构」「优先扩展现有系统，而非推倒重建」。审计结论（报告 1§3、报告 3）：本项目 UI 是 CanvasItem 立即模式 + UISkin 原语 + 热区字典 + 字符串动作路由，**没有任何 Control/Theme**。

| 路线 | 内容 | 优点 | 代价/风险 |
|---|---|---|---|
| **A 扩展立即模式（推荐）** | UISkin 升级为 Token 化设计系统（颜色/字号/圆角/间距常量表）+ 组件化绘制原语；保留 _draw 分发与热区路由 | 输入/拖拽/安全区/震屏隔离/缓动全部已调好，回归面最小；门禁与自检不受影响；性能可控 | 无内建焦点导航/读屏；组件复用靠函数约定而非引擎 |
| B 全量迁移 Control+Theme | 6 屏重写为控件树，Theme 资源，信号连接 | 符合文档字面；引擎级布局/焦点/无障碍 | 输入路由（热区优先于拖拽）、二次确认、安全区、模态动画全部重接；回归面巨大；门禁不覆盖 UI，全靠截图+真机 |
| C 混合 | 战斗 HUD 保留立即模式（性能+震屏隔离），菜单/模态迁 Control | 折中 | 两套体系并存，状态/字体/Token 要双份维护，复杂度最高 |

推荐 A：与文档「先检查现有架构、优先扩展」的总则一致；项目已有 UISkin 这个现成设计系统种子。若用户坚持控件化，建议 C 而非 B，并显著增加工期与验收轮次。

### R2 视觉方向：奶油贴纸（现有）vs 暗色科幻（文档 Token）

- 现有：日系奶油贴纸风（UISkin 15 色，ui_skin.gd:7-21），是此前多轮 deliberate 决策，配套 Blender 3D keyart（hero/logo）、212 张精灵、图标均按此风格渲染（任务 #25-31）。
- 文档：暗色科幻 Token（BG_PRIMARY #081321 / ACCENT_BLUE #26C6F6 / COLOR_GOLD #FFC857 等）。
- 冲突点：换暗色 = UISkin 常量 + 散落硬编码色（报告 5 B3）全量收编；**keyart/logo/精灵是浅色底风格，暗色背景下需评估是否重渲**（美术成本）。
- 选项：① 保留奶油风，只吸收文档的结构/布局/组件/流程改进；② 按文档切暗色科幻（接受美术适配成本）；③ 暗色为主+保留糖果点缀的混合。**需用户拍板。**

### R3 范围裁剪：免费游戏，无内购，不虚构机制

用户明确：不做内购。文档 Phase 4/5 假设的机库/商店/任务/货币/玩家等级在本项目**均不存在**（报告 1§6、报告 4§4）。文档自身红线也不许虚构机制/数值。

| 文档项 | 建议 |
|---|---|
| 商店/货币/内购 | **删除**（免费游戏） |
| 任务 Missions | **删除**（无此系统，不虚构） |
| 玩家等级/永久成长 | **删除**（强化是单局三选一） |
| 机库 Hangar | 跳过；可选替代=只读「武器图鉴/出击预览」（复用 weapon_system 现有数据，零新机制）——**需用户确认是否要** |
| 局内升级（三选一） | 保留，仅卡面视觉优化（Phase 4 实质内容） |
| 独立设置屏 | 建议新增（复用现有 3 开关 + 菜单入口，修 A1/A2，零新机制） |
| 结算/暂停/主菜单/HUD | 按文档优化 |

## 三、建议执行顺序（适配真实架构后）

沿用文档 §8 推荐序 0→1→3→2→4→5→6→7→8，内容按审计裁剪：

1. **Phase 1 设计系统**：UISkin Token 化（颜色/字号/圆角/间距/阴影常量表）+ 收编散点色 + 组件原语整理；字体管线纳入收尾。
2. **Phase 3 战斗 HUD**（最高优先）：布局/层级/可读性优化，保住 D1/D5/D7/D8。
3. **Phase 2 主菜单**：信息层级/入口整理（含设置入口，若 R3 通过）。
4. **Phase 4 升级卡面**：三选一视觉优化（逻辑冻结）；可选武器图鉴（R3）。
5. **Phase 5 结算/暂停/独立设置**：修 A1/A2，C1/C2/C3 按取舍。
6. **Phase 6 UI 生命周期治理**：UIOverlay 状态分发/动画时钟整理（B2 解耦评估），不新造平行 UIManager。
7. **Phase 7 Android 适配/性能**：安全区三态+小窗/宽屏+帧耗测量。
8. **Phase 8 回归+交付**：门禁 180+自检 8+各屏 -shot 真实截图+真机 0 SCRIPT ERROR；出 APK 验签名；版本 v1.5.0/code 23（建议）；push+Release（默认动作）。

每阶段：独立提交（refactor/ui-v2 分支）+ 门禁/自检全绿 + 该屏真实截图，再进下一阶段。
